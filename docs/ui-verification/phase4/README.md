## 本批修复

1. 平板侧导航改为独立滚动容器，短窗口下仍可访问下方入口。
2. 导航补充原生选中语义；关键控件补充稳定测试ID，便于复验。
3. 宽屏设备档案去除重复的手机字段前缀，与表头对齐；窄屏仍保留名称、开放端口等标签。
4. 端口范围、网络信息标签的宽度跟随系统字号，修复“端口范／围”“连接速／率”的生硬换行。最新最大字号截图已复查。

## 测试复现

先按本项目方式构建并签名安装entry及entry_test两个HAP，再运行：

```text
hdc -t <tablet> shell aa test -b com.mu.nettools -m entry_test -s unittest OpenHarmonyTestRunner -s uiAcceptance 1 -s timeout 240000
hdc -t <tablet> shell aa test -b com.mu.nettools -m entry_test -s unittest OpenHarmonyTestRunner -s windowAcceptance 1 -s timeout 240000
```

两项均显式启用；默认测试不操作设备UI。原始结果见 [17项横竖屏回归](tablet-ui-tests.txt) 和 [15项悬浮窗回归](tablet-window-tests.txt)。截图写入应用cache目录后由HDC取回。横竖屏测试检查实际宽高，而非仅按旋转枚举推断方向；运行期间关闭传感器自动旋转，结束后恢复。若设备原先锁定旋转，额外传 `-s rotationEnabled 0`。

业务回归在127.0.0.1:8080临时启动真实TCP服务，验证Ping成功、36个常用端口中的8080开放、127.0.0.1/32单主机发现和档案保存；结束时关闭服务。没有向页面注入演示数据，没有清空用户数据库。会增加本机回环探测记录。

系统分屏通过顶部系统菜单进入，再从桌面选择系统设置配对。本设备UiTest的 `UiWindow.split()` 不支持，未保留一项无法在本机运行的分屏自动化用例；上述分屏结论来自实际系统操作。屏幕朗读下UiTest的常规doubleClick不能触发动作，改用系统uinput的两次50ms触摸、间隔100ms完成核验；同样的方式也能关闭系统设置中的朗读开关。

## 边界与后续

- 悬浮窗测试依次请求320、390、600、834、1194、1440vp，但系统维持窗口比例并限制尺寸，实际都约350vp。**不能据此宣称六种指定宽度已覆盖**；600／834／1194等精确窗口仍待PC实际调整，PC按用户安排稍后接入。
- 分屏当前覆盖竖屏上下配对及短高度；横屏左右分屏尚无本批证据。
- 朗读已验证焦点和操作，没有录制或听辨播报音频；名称、选中、忙碌、错误及复制提示的完整语音顺序仍需人工听测。当前不作完整无障碍合规结论。
- 导出实际写入成功，但设备文件沙箱禁止HDC读取用户文档，未独立解析这两个已保存文件；序列化与导出范围由既有单元测试覆盖。清空只验证弹窗与取消，未删除用户原有数据。
- 检查后恢复浅色、标准字号、默认字重／显示缩放、关闭屏幕朗读并退出分屏；自动测试恢复旋转设置。桌面鼠标悬停、右键及完整键鼠流程待PC验收。

本批状态为“平板主要验收完成，精确窗口矩阵／PC及完整语音听测待补”，不将阶段4标成全平台完成。
